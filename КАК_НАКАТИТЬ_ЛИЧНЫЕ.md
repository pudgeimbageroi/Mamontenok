```sql
-- Тип сделки и владелец
alter table public.deals
  add column if not exists visibility text not null default 'joint'
    check (visibility in ('joint', 'private')),
  add column if not exists owner_id uuid references public.profiles (id);

-- Пересчёт долей: личная сделка = 100% владельцу
alter table public.deals drop column if exists my_share_rub;
alter table public.deals drop column if exists egor_share_rub;

alter table public.deals
  add column owner_share_rub numeric(14, 2) generated always as (
    case
      when visibility = 'private' then amount_cny * (my_rate - atb_rate)
      else amount_cny * (my_rate - atb_rate) / 2
    end
  ) stored,
  add column partner_share_rub numeric(14, 2) generated always as (
    case
      when visibility = 'private' then 0
      else amount_cny * (my_rate - atb_rate) / 2
    end
  ) stored;

-- Касса по тому же принципу
alter table public.cashflow
  add column if not exists visibility text not null default 'joint'
    check (visibility in ('joint', 'private')),
  add column if not exists owner_id uuid references public.profiles (id);

create index if not exists deals_visibility_idx on public.deals (visibility, owner_id);
create index if not exists cashflow_visibility_idx on public.cashflow (visibility, owner_id);

-- Личная запись обязана иметь владельца
alter table public.deals drop constraint if exists deals_private_needs_owner;
alter table public.deals add constraint deals_private_needs_owner
  check (visibility = 'joint' or owner_id is not null);

alter table public.cashflow drop constraint if exists cashflow_private_needs_owner;
alter table public.cashflow add constraint cashflow_private_needs_owner
  check (visibility = 'joint' or owner_id is not null);
```

Все существующие сделки автоматически становятся `joint` — ничего не пропадёт.

# Как это работает

## Три режима (видны только тебе)

Переключатель в правом верхнем углу:

- **🤝 Общий** — совместные сделки, 50/50. Ровно то же самое видит Егор.
- **👤 Личный** — только твои личные, прибыль 100% твоя.
- **📊 Всё моё** — половина от общих плюс все личные. Реальный заработок одной цифрой.

В необ­щих режимах вокруг контента появляется **жёлтая рамка с подписью** — чтобы взгляд сразу цеплял, что на экране личные данные.

Режим хранится в session-куке: **закрыл браузер — вернулся в «Общий»**. Осознанно, чтобы случайно не открыть приложение при Егоре с включённым личным режимом.

## Создание

В форме сделки — тумблер «Общая / Личная» (у Егора его нет вовсе). В личном режиме тумблер сразу стоит на «Личная», но переключаемый.

Тип задаётся **только при создании** и потом не меняется. Причина: перевод общей сделки в личные выглядел бы для Егора как бесследное исчезновение строки.

То же самое в кассе — операции тоже бывают личными.

## Что видит Егор

Ничего. Не список без строк, а именно ничего:

- сделки отфильтрованы во всех запросах
- счётчики, обороты, средний чек — только по общим
- балансы счетов — только общие потоки
- прямая ссылка `/app/deals/<uuid>` на личную → **404**, факт существования не раскрывается
- уведомления по личным не уходят ни в группу, ни ему в личку
- бот вообще не знает о существовании личных сделок

## Архитектура защиты

Всё чтение идёт через `lib/deals-query.ts` — прямых `supabase.from("deals")` для чтения в коде больше нет. Фильтр применяется автоматически, забыть его негде.

Правило: **deny by default**. Если режим не запрошен явно и пользователь не владелец — только общие данные.

Провёл аудит всех 13 точек доступа к данным: 8 чтений с фильтром, 5 записей после проверки прав. Попутно нашёл и закрыл дыру — `DELETE /api/cashflow/[id]` позволял удалить любую операцию по прямому ID без проверки владельца.

## Два ограничения, о которых стоит помнить

**Реальный баланс банка ≠ общий баланс в приложении.** Личные сделки двигают деньги через тот же счёт АТБ. Если когда-нибудь сверитесь с настоящей выпиской — разница будет видна. Это неизбежно при такой схеме.

**Доступы решают всё.** Сейчас у Егора только приложение, поэтому фильтрация в коде — реальная защита. Приложение ходит в Supabase под `service_role`, то есть RLS не применяется. Если однажды выдашь ему доступ в дашборд Supabase, он увидит таблицу целиком, включая всю историю личных сделок задним числом.
